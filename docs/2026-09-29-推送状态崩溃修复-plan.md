# 推送状态崩溃修复计划（2026-09-29 生产事故）

> 事故性质：本机与云端共享的推送状态落盘崩溃 → 状态截断损坏 → 容缺加载 → 去重失效 → 每 5 分钟全量重推洪水。
> 本计划只修事故本身；切流（SCF Task 6）、打包遗留（config_path）各自独立计划。

## 背景与根因（已取证，执行者不必重查）

1. **症状（本机）**：`logs/round.log` 自 2026-09-29 10:25 起间歇出现 `TypeError: Object of type Signal is not JSON serializable`；每个 error 轮之后的下一轮重发 6 条 breaking + 1 条 alert（10:25/10:40/11:40/12:10/13:35/15:00/15:10 各 6 条 breaking，14:30/15:00/15:10 各 1 条 alert），钉钉群真实收到重复消息。
2. **根因A（崩溃源）**：`render/push_policy.py` `plan_push()` 第 2 步 `item = dict(t)` 把 topic 的 `signals` 字段（Signal 对象列表，`main.py:90` 证实 topic 含该字段）浅拷进 `state["a_pending"]`；`save_state()` 的 `json.dump(state, f)` 无 `default`，写到 `signals` 即抛 TypeError。
3. **根因B（洪水放大器）**：`save_state` 先 `open(path, "w")` 截断目标文件再序列化 → 崩溃留下截断文件（已抓到现行：`states/push_state.json` 443 字节，尾部停在 `"signals": [`）；`load_state` 异常容缺返回 `{}` → `plan_push` 按空状态重新规划 → 当日去重（`pushed`/`breaking_count`/`alert_date`）全部失效 → 全量重推。
4. **根因C（云端静默循环）**：`scf_handler.handler` 中 `run_round` 抛异常 → `sync_up` 不执行 → COS `data/states/push_state.json` 冻结在 2026-09-29 15:21:35（之后每轮触发报错、状态不推进；当前规划不出新消息所以不发推，但 21:00 后 `daily_done` 分支会每轮重发晚报）。
5. **止血现状（执行者必须知道，不要回滚它）**：本机计划任务 `HotPredict-Round` 已 `Disabled`（回滚命令 `Enable-ScheduledTask -TaskName HotPredict-Round`）；云端触发器 `every5min` 保持启用。**本任务不恢复本机计划任务**——恢复与否由后续切流任务决定。
6. **附带事实**：云端 CLS 未注册，`GetFunctionLogs` 恒为 0（Task 5 已记录），日志验证只能靠 invoke 返回的 `LogType=Tail` 与 COS 对象时间戳。
